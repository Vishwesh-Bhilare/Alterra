Document control and scope
This document consolidates the hybrid architecture described in the supplied 10-page ALTERA architecture PDF with the seven proposed metrics supplied in the request. The architecture source proposes a rule-based cognitive doctrine, an LSTM that estimates per-band utility, candidate masking, rule-based dwell, imitation learning from the existing heuristic, and optional PPO fine-tuning.

Executive summary
Recommended architecture: preserve the heuristic scheduler as the rule engine and teacher; use an LSTM policy/value model to exploit temporal observations; apply a valid-action mask; keep dwell rule-based for the first version; and add PPO only after a supervised imitation baseline is stable.
The seven proposed formulas are not all interchangeable and should not all be used as training objectives. They belong to different layers: receiver/detector performance, end-to-end scheduling outcomes, reinforcement-learning optimization, and model diagnostics. The recommended core evaluation set is interception rate, event-level interception probability or recall, detection probability and false-alarm probability (where detector-level labels exist), reward/cost, and coverage/latency/redundancy. Accuracy and intercept-time error are supplementary and must be carefully defined.
Key formula correction: The proposed Pd, Pfa, sensitivity, average interception rate, episodic reward, accuracy, and MAE formulas are broadly valid under stated definitions. Important caveats: count independent/defined opportunities, avoid treating band-time cells as independent events, use a clear unit for rate, include episode aggregation choices, and do not use classification accuracy as a substitute for detection or scheduler success.
1. Architecture overview
The design principle is: “Rules control the doctrine; ML controls decisions within that doctrine.” The rules define what modes and actions are admissible; the learned model estimates which admissible band is valuable under the recent observation history.

1.1 Runtime sequence
Reset the environment and initialize episode state, history buffer, scan counts, coverage and target/event bookkeeping.
Receive the observation available to the scheduler; construct the normalized state vector and update the sequence buffer.
Run the rule engine to determine operating mode and construct a candidate mask. Hard safety or simulator constraints must not be overridden by ML.
Pass the observation sequence through the LSTM. Produce one score/logit per band.
Apply the valid-action mask. If no valid action remains, invoke a documented fallback that relaxes only designated soft constraints; never relax hard safety constraints.
Select the band (sample from masked policy during RL training; use deterministic highest-probability valid action for evaluation).
Choose dwell using the rule-based dwell controller; execute the scan in the simulator.
Use simulator ground truth only for reward and offline evaluation, not as an unobservable policy feature.
Update coverage, history, detection/interception event records, episode reward/cost and diagnostics. Repeat until termination or truncation.

2. State, action, reward and episode definitions
2.1 Observation/state design
The policy input must contain only information that would be available to the scheduler at decision time. A practical initial feature schema is below; retain only fields supported by the current ALTERA environment.
Feature group
Candidate features
Notes
Band state
Per-band recently observed flag, time since last scan, scan count, coverage/visit status.
Use a 128-element vector or equivalent, if there are 128 bands. Normalize counts/times.
Detection evidence
Recent detection score/confidence, detection history or observable event evidence per band.
Define missing-value handling and ensure features reflect receiver observations, not simulator truth.
Global state
Current coverage fraction, elapsed episode fraction, total scan budget remaining.
Global features may be concatenated with per-band features or repeated as needed.
Doctrine state
Current mode, track status or remaining allowed track revisits, relocation flag.
Encode categorical variables consistently, e.g., one-hot.
Action history
Previous band, previous dwell, recent action sequence.
LSTM can use this history; avoid duplicating history excessively if state already summarizes it.
Use a fixed sequence length K initially (select by validation, not intuition alone). Each sequence is X_t = [o_(t-K+1), …, o_t]. Pad early episode history and provide a mask if needed. Standardize continuous features using training-set statistics only, then apply the same transform to validation/test.
2.2 Action space
v1 action: discrete band index a_t ∈ {0,…,N−1}, with N=128 only if confirmed by the environment. Dwell is selected by a separate deterministic/rule-based controller. This factorization reduces the initial learning problem.
Do not silently encode dwell into the action as a 128×D joint action in v1. If dwell is later learned, compare a factored policy (band policy plus dwell head) against the staged design and update the mask, reward and action-space documentation.
2.3 Reward and cost design
Reward is a project-specific optimization signal, not a standardized physical metric. Keep the reward transparent, logged by component, and separate from the external evaluation metrics.
r_t = w_I · I(new valid interception) + w_D · D_t − w_F · FP_t − w_R · R_t − w_T · Δt_t − w_C · C_t
This is a template, not a final numeric reward. Define each term precisely before training:
I(new valid interception): 1 only for a newly counted interception event under the event-deduplication convention; otherwise 0.
D_t: optional detector-level success contribution, if not double-counting the interception reward.
FP_t: false-alarm penalty using a defined false-alarm event or rate contribution.
R_t: redundant/unjustified revisit penalty; avoid penalizing legitimate tracking revisits.
Δt_t: elapsed simulated time or scan-time cost, with units stated.
C_t: any additional resource cost actually represented in the simulator.
Choose weights using a documented scale/sensitivity study. Do not tune weights on the final test scenarios. Report reward components and real-world-style outcome metrics separately so a reward improvement cannot hide a decline in detection, coverage or latency.
2.4 Episode and event definitions
Episode: one simulator run with a defined start, termination condition, emitter scenario and random seed.
Transmission opportunity: a ground-truth event that overlaps the receiver’s observable time/frequency conditions and is eligible for evaluation. State whether events outside the receiver’s configured range are excluded.
Distinct interception: a successful receiver observation assigned to a unique event ID under a fixed deduplication rule. Multiple pulses/observations from one event do not increase the distinct-event count.
Detection trial: one defined detector decision under H1 (signal present) or H0 (signal absent). Define whether the trial is a pulse, time-frequency cell, dwell window or event-level decision.
Time-to-intercept origin: use emitter/event onset as the primary origin; record censoring for events never intercepted by episode end.

3.2 Metric 1 — Probability of Detection (P_D)
User-provided definition: P_D = P(detection | H1). The empirical estimator P_D = TP/(TP+FN) is correct when TP and FN are counts of the same defined detection trials under H1.
P_D = P( declare signal | H₁ )  ≈  TP / (TP + FN)
ALTERA implementation: define an H1 trial unit (e.g., an eligible detector decision window with a signal actually present). TP is a positive detector declaration in that trial; FN is a missed declaration. Do not mix transmission events, individual pulses and band-time cells in one denominator. If multiple observations correspond to one event, specify whether the metric is pulse-level, dwell-level or event-level.
Interpretation: P_D measures detector performance conditional on a signal being present in the detector’s defined input/trial. It is not the same as the probability that the scheduler tunes to the correct band during the transmission. End-to-end interception incorporates scheduler opportunity, timing overlap, receiver availability and detector success.
Recommended reporting: estimate across all eligible H1 trials, and also report per scenario/SNR or condition where applicable. Include the number of positive trials and uncertainty intervals (e.g., binomial confidence intervals) when sample size permits.
3.3 Metric 2 — Probability of False Alarm (P_FA)
User-provided definition: P_FA = P(detection | H0). The empirical estimator FP/(FP+TN) is correct when FP and TN are counts of defined H0 trials.
P_FA = P( declare signal | H₀ )  ≈  FP / (FP + TN)
ALTERA implementation: H0 trials are detector decision windows with no signal under the ground-truth definition. FP is a signal declaration in H0; TN is a no-signal declaration. Define how clutter, interference, overlapping emitters or unmodeled signals are labeled. A non-signal window is not necessarily “noise only” unless the simulator says so.
Report P_D and P_FA together at the same detector threshold and conditions. If threshold is tuned, use validation data and freeze it before test. A ROC curve (P_D versus P_FA over thresholds) can be included if detector scores are available. Detector performance depends on threshold and signal/noise conditions; this is consistent with standard ROC treatment in radar detection references [1,2].
3.4 Metric 3 — Receiver sensitivity
The proposed thermal-noise expression is a useful engineering approximation, but it should be written with care. A common input-referred minimum detectable signal expression is:
P_min ≈ k T₀ B F · SNR_min
Here F is the linear noise factor (not noise figure in dB), B is equivalent noise bandwidth in Hz, and SNR_min is a linear ratio. This expression assumes a stated reference temperature, matched/consistent bandwidth and a specified required SNR at the detector input. It omits implementation losses, processing gain, mismatch, quantization, integration effects and any additional detection criterion unless these are folded into an effective threshold.
P_min,dBm ≈ −174 dBm/Hz + 10 log₁₀(B in Hz) + NF_dB + SNR_min,dB
At approximately 290 K, −174 dBm/Hz is the thermal-noise density. The dB expression is dimensionally consistent when B is in Hz and NF is in dB. Do not add a dB-valued NF to the linear-power expression; use F_linear there. State whether the simulator implements noise figure and receiver bandwidth physically or merely uses a detection threshold.
Decision: do not treat sensitivity as an outcome of the scheduler or as an ML metric. If ALTERA has a receiver/noise model, document the sensitivity parameter and keep it constant across scheduler comparisons. If it does not, omit numeric sensitivity claims and state that sensitivity is outside the simulated model. A more negative P_min indicates lower minimum detectable input power under the same assumptions.
3.5 Metric 4 — Average interception rate
The formula is valid as a throughput-style measure when N_I counts distinct successful interceptions and T_obs is a consistent elapsed observation duration.
R_I = N_I / T_obs
Mean episode rate = (1/M) Σ[m=1…M] (N_I,m / T_m)
The user-provided episode-average formula gives equal weight to each episode’s rate. This is appropriate when episodes are the sampling units and an equal-episode average is intended. If the objective is total interceptions divided by total observation time, also report the pooled rate:
R_pooled = (Σ N_I,m) / (Σ T_m)
These two aggregation choices can differ when episode durations differ. State which is primary; recommended: report pooled rate and mean per-episode rate, especially if episode durations vary. Deduplicate by unique event ID so multiple pulses from one transmission do not inflate N_I. Define whether an interception requires only a detector declaration or successful event association/validation.
Decision: use as a primary end-to-end scheduling metric, alongside event interception probability/recall and coverage. It measures count per unit time, not probability.
3.6 Metric 5 — Average reward / cost
The discounted episodic return formula is valid if the intended quantity is discounted return and γ is applied from the episode’s time origin.
G_m = Σ[t=0…T_m−1] γᵗ r_m,t
Mean episodic return = (1/M) Σ[m=1…M] G_m
For a finite-horizon task, γ=1 may be appropriate if all rewards/costs within the episode should count equally and the horizon is fixed. For γ<1, later rewards are discounted. State γ, reward scaling, episode horizon and whether reward is normalized. Do not compare returns across reward definitions or different γ values as if they were the same metric.
The separate average cost formula is valid once C_m is defined consistently:
Mean cost = (1/M) Σ[m=1…M] C_m
Decision: use return to train/evaluate the RL agent and log reward components. Report interpretable costs (elapsed time, scan count, false alarms, redundant revisits) separately. Do not divide reward by cost unless there is a clear decision-theoretic justification, a nonzero denominator and a stated interpretation.
3.7 Metric 6 — Percentage of correct predictions (accuracy)
The formula is correct for binary classification when TP, TN, FP and FN all refer to the same labeled decision unit.
Accuracy = (TP + TN) / (TP + TN + FP + FN) × 100%
Decision: supplementary detector/classifier diagnostic only. If most band-time trials are H0, a trivial “no signal” classifier may have high accuracy while missing transmissions. Always report the confusion matrix and P_D/P_FA. Precision = TP/(TP+FP) can be added if false declarations are operationally relevant; define behavior when a denominator is zero. Balanced accuracy may be useful under class imbalance, but do not replace P_D/P_FA with it.
Important scope distinction: accuracy should not be used to score the band-selection policy unless the policy itself is explicitly trained to predict ground-truth occupancy labels. Scheduler action quality should be evaluated by environment outcomes and baseline comparisons.
3.8 Metric 7 — Average interception-time error
The proposed mean absolute error is mathematically valid for paired, valid predicted and actual times:
MAE_time = (1/N_valid) Σ[i in valid paired events] | t̂_i − t_i |
Decision: optional secondary metric only. The v1 architecture does not require the LSTM to predict an interception timestamp; it selects a band. Include this metric only if you add a separate time-to-intercept prediction head or a defined predicted-time estimator.
Use a consistent time origin (recommended: event/transmission onset). Report N_valid and coverage of predictions, and separately report events never intercepted by episode end as missed/censored outcomes. Do not calculate MAE only on easy intercepted events without disclosing the exclusion, because this creates selection bias. For a scheduler without a time-prediction output, report actual time-to-first-intercept distribution and fraction not intercepted by horizon instead of “prediction error.”

5. Training plan
5.1 Stage A — Generate teacher trajectories
Run the current rule-based scheduler across a diverse training scenario set and multiple random seeds.
Log each decision-time observation, observation history, mode, valid-action mask, selected band, dwell, next observation, event outcomes and reward components.
Split by scenario/seed, not by randomly splitting adjacent timesteps from the same trajectory. Keep test scenarios/seeds isolated from model fitting and hyperparameter selection.
Check label diversity: if the heuristic always chooses a narrow set of bands, include scenarios that exercise explore, investigate, track and relocate modes.
Version the simulator configuration, doctrine parameters and data-generation code.
5.2 Stage B — Supervised imitation learning
Model: sequence encoder (LSTM) → linear output head of N band logits. Use a masked cross-entropy objective against the teacher-selected band. For each training sample, the teacher action must be valid under the stored mask.
L_imitation = −(1/B) Σ[b=1…B] log πθ(a_teacher,b | X_b, M_b)
Use training-only feature normalization, validation-based early stopping, class/action distribution inspection and held-out scenario evaluation. Measure both teacher-action agreement and environment outcomes. Teacher agreement is a training diagnostic, not the ultimate success metric.
5.3 Stage C — Optional PPO fine-tuning
For PPO, the policy must output a probability distribution over valid actions and a value estimate. The LSTM can be part of a recurrent actor-critic, but the recurrent hidden state, sequence minibatches, episode resets and masks must be handled consistently.
πθ(a | X,M) = Softmax(masked logits);  a ∈ valid actions
During rollout, store observations/sequences, action masks, sampled actions, old log-probabilities, rewards, termination/truncation flags, value estimates and recurrent states as required by the implementation. Train using PPO’s clipped policy objective and value/entropy terms. Use a recurrent-PPO implementation that supports action masking, or implement and test this combination explicitly.
Implementation compatibility warning: The stable-baselines3-contrib MaskablePPO documentation lists recurrent policies as unsupported. Do not assume MaskablePPO can be combined directly with an LSTM recurrent policy. Options: (a) use a supported recurrent PPO implementation with masking; (b) implement custom recurrent masked PPO; or (c) for a simpler v1, use non-recurrent MaskablePPO with a state vector that explicitly includes sufficient history. Verify library versions and API behavior before committing.
PPO is optional. If the team cannot validate recurrent masked PPO within the project timeline, a well-evaluated imitation LSTM with rule-based masking is a valid prototype milestone. Do not claim RL improvement without held-out evaluation.

6.2 Gymnasium interface contract
Use the Gymnasium reset/step pattern: reset returns (observation, info); step returns (observation, reward, terminated, truncated, info). The environment should distinguish a true terminal condition from an externally imposed time limit. Put evaluation-only ground truth and detailed event bookkeeping in info/logging, not in the policy observation unless it is genuinely observable.
The official Gymnasium documentation describes this reset/step API and supports custom environment implementations [3].
6.3 Action-mask contract
Return a Boolean mask of length N for each decision, where True means selectable.
Generate the mask from current environment state and doctrine before policy selection.
Apply the mask to logits/probabilities consistently in training, sampling and evaluation.
Assert mask length equals action-space size and at least one action is valid, or invoke the documented fallback.
Log why each candidate was removed (hard constraint versus soft preference) to debug excessive masking.
6.4 Reproducibility and logging
Record global seed, scenario ID, simulator version, code commit, configuration hash and model checkpoint.
Store per-step timestamp, mode, mask, selected band, dwell, reward components, detections, unique event IDs and coverage state.
Use paired scenario/seed comparisons where possible to reduce variance between policies.
Report mean and dispersion (standard deviation or confidence interval) across episodes; avoid reporting only the best run.
Preserve a frozen test set and do not select a checkpoint based on test results.

8. Formula and metric implementation checklist
P_D: TP+FN > 0; all counted trials are H1 and use one stated trial unit.
P_FA: FP+TN > 0; all counted trials are H0 and use the same decision-window convention.
Confusion matrix: define positive class as “signal declared/present” consistently.
Sensitivity: use linear F and linear SNR in the linear expression; use NF_dB and SNR_dB only in the dBm expression.
Interception rate: deduplicate successful interceptions by event ID; record total observation time in stated units.
Rate aggregation: report pooled rate and mean episode rate if episode durations vary.
Reward: freeze reward definition and γ for comparisons; log components and separately report interpretable costs.
Accuracy: do not present alone under class imbalance; pair with P_D, P_FA and confusion counts.
Intercept-time MAE: include only with a real prediction output; disclose valid-event count and censoring/non-intercepts.
Coverage: define the denominator (all configured bands or all eligible bands) and whether coverage is ever-scanned or recently scanned.
Latency: state whether measured wall-clock inference time or simulated decision time; do not conflate them.

11. Final implementation decision
Decision: Proceed with Hybrid v1: existing rule doctrine + LSTM band-scoring model + valid-action mask + rule-based dwell + feedback logging. Train first by imitation learning. Add PPO only after the first model and evaluation harness are stable, and only with an implementation that correctly supports the chosen recurrent/masked policy design.
Use the seven supplied formulas selectively and with precise denominators. P_D and P_FA are detector metrics; sensitivity is a fixed receiver condition; interception rate is a primary end-to-end scheduler metric; episodic reward is an RL objective/diagnostic; accuracy is supplementary; and intercept-time MAE is optional unless a time-prediction head is added.
The team should not claim the scheduler is “better” until a frozen test-set comparison shows the relevant measured improvements over the existing rule-based baseline, with trade-offs and limitations reported.
